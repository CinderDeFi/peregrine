# Peregrine v0.1 — public scaffold

> **This is an unaudited scaffold.** It has never been deployed, it holds no
> value, and there is no token. It is a complete, working demonstration of every
> subsystem — published so the architecture can be read, run, and criticised, not
> so that anyone runs it in production. The limitations list below is longer than
> the pitch, and that is on purpose.

Peregrine is a data-native, real-time Layer-1: signed high-frequency records ride
*inside* consensus dissemination instead of queueing behind blocks, commit to a
deterministic order, and materialize into Merkle-verifiable tables. A light
client holding 32 bytes can verify any read — in a browser, in a contract, on
another chain. The premise is *verify, don't trust*: every read carries a proof
you check yourself.

## Try it in ten seconds

```bash
git clone https://github.com/peregrine-labs/peregrine && cd peregrine
cargo install --path crates/peregrine-cli      # or: cargo run -p peregrine-cli --
peregrine -q demo                              # the whole tour
```

`peregrine demo` stands up a **4-validator devnet over a real QUIC mesh** and
runs four acts end to end in about ten seconds:

1. **Streams** — 25 signed price ticks published, committed, and materialized.
2. **TalonVM** — a metered on-chain loop sums `1..=10 → 55`.
3. **Light client** — a genuine inclusion proof verifies; a tampered value and a
   proof against the wrong root are both rejected.
4. **Ethereum interop** — a contract reading unverified foreign state *traps*
   rather than returning zero; a claim with no ZK proof is refused.

No RPC provider, no faucet, no configuration. It runs against real consensus.

## What's in this release

- **Consensus + data plane.** DAG-ordered BFT with signed records disseminated
  inside consensus; deterministic commitment into path-compressed sparse Merkle
  trees. Sustained ceiling **~34,000 records/s**; **19,993 records/s at p50
  4.19 ms** on a 4-validator loopback run (one laptop — treat latency as a floor,
  not a finality claim). Reproduce with `peregrine bench`.
- **Ethereum → Peregrine.** Ethereum state is verified inside a zkVM and
  re-checked by *every* validator at commit time, with the guest image pinned. A
  real SP1 proof verifies **in the commit path in ~52 ms**. Tested against real
  mainnet data — reproduced block hashes, real `eth_getProof` responses, a real
  510/512 BLS aggregate signature.
- **Peregrine → Ethereum.** An EVM light client (`contracts/`) wired to SP1's
  **real on-chain Groth16 verifier** (vendored at the exact circuit version),
  doing the full BN254 pairing over five immutable pins. No mock in the
  verification path.
- **Verifiers in three languages, kept in lockstep.** The Rust, TypeScript, and
  Solidity verifiers are checked byte-for-byte against Rust-generated fixtures in
  CI, so they cannot silently drift.
- **A path-compressed Merkle upgrade** (62 µs → 2 µs per row) shipped as a
  *versioned consensus upgrade* gated on a committed round, not a silent
  optimisation — old proofs are refused against new roots, both directions
  tested.

## Security posture

Before this release an internal security review covered the ~3,660
consensus-critical lines. It found a real one — a consensus round-structure check
written as a `debug_assert`, compiled out of release builds — plus five
lower-severity items. All are fixed and written up with resolutions in
[`AUDIT.md`](../AUDIT.md), alongside the scope, trust boundaries, nineteen named
invariants, a threat model, and a ranked list of what to attack first.

**Still true, and stated plainly:** not third-party audited, never deployed, no
token. Committee rotation for the Ethereum → Peregrine direction is not
implemented (the EVM client pins its validator set immutably), and equivocation
is detected but not slashed. Both are in `AUDIT.md`.
