# @peregrine/sdk (TypeScript)

A light client for Peregrine that runs in browsers, edge runtimes, and Node —
built around one idea: **verify, don't trust.**

```ts
import { PeregrineClient, tableId } from "@peregrine/sdk";

const client = PeregrineClient.http("http://localhost:8080/rpc");

// Fetches the value *and* its inclusion proof, then re-derives the state root
// locally. Throws if the value doesn't reconstruct the root you trust.
const row = await client.readVerified(tableId("contract.answers"), "73756d");
console.log(row?.value);
```

## What this package actually is

The valuable, transport-independent half of a light client: a **complete
reimplementation of Peregrine's proof verification** in TypeScript.

A `ProvenRead` chains two proofs, and this package checks both:

1. a **sparse-Merkle** path proving `(key, value)` occupies its slot under the
   table root (the same path proves *absence* when the value is `null`);
2. a **binary-Merkle** path proving `(table, tableRoot)` sits in the store under
   the store root.

If `verifyProvenRead` returns true, the value is in committed state under the
root you supplied. The node that served it is irrelevant — that's the point.

### Cross-language correctness

A light client that verifies *differently* from the chain is worse than none,
so this isn't verified by hand-written vectors. `test/fixtures/proven-read.json`
holds **real proofs generated by the Rust node**:

```bash
cargo run -p peregrine-node --example gen_js_fixture   # regenerate
```

The test suite checks those genuine proofs verify, and that tampered values,
wrong roots, corrupted paths, replayed keys, and truncated paths all fail. It
also asserts `tableId(name)` matches Rust's `TableId::named` byte for byte.

```bash
npm install
npm test        # 18 tests
npm run example
```

## Transport — read this before wiring it up

Peregrine nodes speak **QUIC**. Browsers cannot open raw QUIC sockets and
Node's QUIC support is still experimental, so **this package does not dial a
validator directly.** It targets a small JSON gateway in front of a node's RPC
endpoint, via a swappable `Transport`:

* `HttpTransport` — `POST`s the documented JSON shapes to a gateway URL.
* your own — implement `Transport` over WebTransport, a WebSocket, or a mock.

**The gateway does not ship in this scaffold yet.** Today the Rust SDK
(`peregrine-sdk`) is the way to talk to a live node; this package's client is
API-complete and fully tested against a stub transport, and its verifier works
against any proof you can obtain.

That gap is deliberately *not* a security problem: because `readVerified`
re-checks every value locally, a gateway — or any future transport — can
withhold data but can never forge it.

## API

| Function | Purpose |
| --- | --- |
| `verifyProvenRead(read, root)` | Verify a value against a trusted store root |
| `verifySmt(key, value \| null, proof, root)` | Row inclusion **or absence** in a table |
| `verifyMerkle(leaf, proof, root)` | Store-level inclusion |
| `provenReadFromJson(json)` | Decode the hex wire form |
| `tableId(name)` | Derive a table id (matches Rust `TableId::named`) |
| `PeregrineClient.readVerified(table, key, root?)` | Read + verify, throws on a bad proof |
| `PeregrineClient.proveRead/storeRoot/publish/submitTx/ping` | Raw RPC calls |
| `fromHex` / `toHex` / `readU64LE` / `digest` / `combine` | Byte + hash helpers |

## Notes and limits

* Runs directly off `.ts` sources under Node ≥22.6 type stripping — no build
  step. That means **no TypeScript parameter properties, enums, or namespaces**
  in this package (strip-only mode can't emit code for them).
* Proofs carry the full 256-sibling sparse-Merkle path, so a `ProvenRead` is
  ~8 KB. Compressing to the non-default siblings plus a bitmap is a protocol
  change tracked on the Rust side; this verifier follows whatever the node
  emits.
* `publish` and `submitTx` take pre-encoded payloads: record **signing**
  (ed25519 publisher keys) and Talon program encoding are not yet implemented
  in TS. Use the Rust SDK to publish today.
* One dependency: [`@noble/hashes`](https://github.com/paulmillr/noble-hashes)
  for BLAKE3.
