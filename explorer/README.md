# Peregrine Explorer

A block explorer for Peregrine — with one difference from every other explorer:
**it does not ask you to trust it.** Every value it shows is fetched with an
inclusion proof and re-verified in your browser against the committed store
root. A hostile or buggy gateway can withhold or stall data, but it cannot forge
a value: a tampered proof fails the local check.

It contains no cryptography of its own. It drives the real
[`@peregrine/sdk`](../sdk/js) — the same verifier the light client and the
on-chain contract use — so it cannot quietly disagree with the chain.

```
explorer/
├── index.html          the UI (self-contained styling)
├── app.js              polling, rendering, search, tamper demo
├── demo-transport.js   a Transport backed by bundled real proofs (offline mode)
├── demo-data.json      real Rust-generated proofs (2 committed snapshots)
├── vendor/
│   └── peregrine-sdk.js  the SDK, bundled for the browser (esbuild)
└── test-explorer.mjs   headless test of the transport → verify path
```

## What it shows

Peregrine's public surface is deliberately small — the honest head is the
**store root**, and anything else you want to believe you prove. The explorer
leans into that rather than fighting it:

- **Store root** — the 32-byte verifiable head, polled live.
- **Commits** — a timeline of committed roots this client has observed. There is
  no trusted "latest block" feed to relay; each root *is* a committed frontier.
- **Verified state** — tables, stream ticks, and cross-chain claims, each read
  with a proof and marked **✓ verified** / **✗ forged** by *your* browser.
- **Search** — look up any `table:key`, verified locally. Flip **tamper** on to
  corrupt the value before verifying and watch the check reject it.

## Run it

The explorer is static files, but it uses ES modules and `fetch`, so it must be
**served over HTTP** — opening `index.html` from `file://` will not work.

### Offline demo (no node, works on GitHub Pages)

```bash
cd explorer
python3 -m http.server 8000      # or: npx serve .
# open http://localhost:8000
```

The demo serves real proofs generated by the Rust node and verifies them for
real — including the tamper rejection. It cycles through two committed snapshots
so the head visibly moves.

### Against a live node

A browser cannot speak the node's QUIC RPC directly, so run the gateway (a small
HTTP↔QUIC bridge, read-only, CORS-enabled):

```bash
peregrine node run                       # terminal 1: a devnet with an RPC endpoint
peregrine gateway --node <rpc_addr>      # terminal 2: defaults to http://127.0.0.1:8080
cd explorer && python3 -m http.server 8000
# open http://localhost:8000/?gateway=http://127.0.0.1:8080/rpc
```

`peregrine node run` prints its RPC address; `peregrine gateway` prints the HTTP
URL to pass as `?gateway=`. Publish some data with `peregrine submit-tx` or
`peregrine sdk example publish-stream`, then watch it appear — verified.

## Deploy to GitHub Pages

The `explorer/` directory is self-contained and needs no build to serve. Point
Pages at it (or copy it into your Pages branch). It runs in offline-demo mode by
default; anyone can append `?gateway=…` to aim it at their own node.

## Rebuilding the vendored SDK / demo data

Both artifacts are committed so the site works with zero build. Regenerate them
only when the SDK or the fixtures change:

```bash
# bundle the SDK for the browser
cd sdk/js
npx esbuild src/index.ts --bundle --format=esm --platform=browser \
  --outfile=../../explorer/vendor/peregrine-sdk.js

# rebuild demo-data.json from the cross-language proof fixtures
node ../../explorer/build-demo-data.mjs
```

## Test

```bash
node explorer/test-explorer.mjs
```

Drives the `DemoTransport` through the real client and asserts that every proof
verifies against its snapshot's root, is refused against a foreign root, and
that tampered values are rejected.
